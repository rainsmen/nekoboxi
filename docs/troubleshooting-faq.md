# ThBox 常见问题与排查指南 (FAQ)

本文档汇集了 ThBox for Android 客户端在安装、运行、DNS 分流与系统兼容性方面的常见问题排查建议。签名历史适用于所列发布版本；独立 Preview、v2 备份、资产校验与新界面说明适用于 2026-11 开发分支，不能据此推断已发布的 1.6.0 已包含全部功能。

---

## 1. 安装与更新相关

### Q1: 从旧版覆盖安装提示“软件签名证书不一致，需要卸载重装”？
- **1.5.5 及更早的版本**：当时 CI 每次构建都临时生成随机密钥，APK 的签名证书各不相同。这些版本必须**先在应用内备份配置，再卸载**，安装新版本后恢复备份。
- **1.5.6、1.5.7**：可以直接覆盖安装 1.6.0。1.6.0 起发布版改用新的签名密钥，APK 中带有旧密钥到新密钥的授权链（APK v3 密钥轮换），系统会认可新密钥，不需要卸载。
- **1.6.0 及以后**：以后的版本都可以直接覆盖安装，跳过中间版本也可以。
- **本分支预览版（Actions 构建产物）**：显示名称为 ThBox Preview，包名带 `.preview`，与正式版共存，数据分别保存。以前同包名、只用旧密钥签名的 Preview 不能覆盖已轮换签名的正式版；这不等同于 Secrets 配置错误。
- 签名原理和发布流程见 [`release-signing.md`](release-signing.md)。

### Q2: ThBox 能和 NekoBox / NB4A 同时安装吗？
- 可以。ThBox 的包名是 `io.github.rainsmen.thbox`，与 NekoBox / NB4A 不同，Android 把它们当作两个应用。
- 因此 ThBox 也不能覆盖升级 NekoBox，节点需要从 NekoBox 导出后再导入。

## 2. 节点连接与运行错误

### Q3: 开启 VPN 后网页无法打开，但节点测速正常？
- **排查步骤**：
  1. **检查 DNS 配置**：进入“设置” -> “路由与 DNS”，确认“远程 DNS”与“直连 DNS”均已正确配置。推荐直连 DNS 使用 `local` 或运营商推荐 DNS，远程 DNS 使用主流公共 DoH（如 `https://1.1.1.1/dns-query`、`https://8.8.8.8/dns-query`）。
  2. **FakeIP 兼容性**：若开启了 FakeDNS（FakeIP），部分不支持虚假 IP 回源的国内应用可能异常。可在设置中尝试关闭 FakeDNS，或在分流规则中将这些应用/域名加入“Direct”（直连）。
  3. **绕过局域网**：确认“绕过局域网地址”已勾选，防止局域网打印机、NAS 等连接被截获。

### Q4: 开启 FakeDNS 后启动失败，提示 `dns.rules[N].disable_cache: json: unknown field "disable_cache"`？
- 1.6.0 之前的测试版中，FakeDNS 与“仅 IPv4 / 仅 IPv6”同时开启时会生成 sing-box 1.14 不接受的规则。已在 1.6.0 正式版修复，升级即可。

### Q5: Hysteria2 节点全部超时，日志只有 `context canceled`，没有其他错误？
- `context canceled` 只表示操作被取消，不能单独确定服务端或网络故障。先查看同一次连接之前的 DNS、握手和超时错误，再检查节点有效性与 UDP 连通性；切网、停止服务或测速取消也可能产生该信息。
- 如果日志中出现 TLS 握手错误，且服务端使用 Ed25519 证书，可在节点设置中打开“禁用 Chrome QUIC 指纹”。
- 建议用另一个客户端确认节点可用后再排查。

### Q6: 订阅里的 Hysteria2 / Snell 节点能导入吗？
- Clash 订阅中的 `hysteria2`（含 `obfs`）和 `snell`（v4、v6）节点可以导入。
- Snell 没有通用的分享链接格式，只能通过订阅导入或手动新建。

## 3. 系统权限与后台保活

### Q7: 在部分国产定制系统（小米 HyperOS、华为 HarmonyOS、vivo OriginOS、OPPO ColorOS）上后台频繁断连？
- **排查建议**：
  1. **电池策略**：在系统“设置” -> “应用管理” -> “ThBox” 中，将“电池优化”设置为“无限制 / 不优化”；
  2. **自启动与关联启动**：允许 ThBox 的“自启动”和“后台运行”权限；
  3. **后台任务锁定**：在多任务界面下拉锁住 ThBox 任务卡片，防止系统一键清理后台时误杀 `:bg` 代理守护进程。

### Q8: Android 13 及以上没有常驻通知或网速显示？
- 首次运行时需要授予通知权限。拒绝后代理仍可正常使用，只是不显示通知。可在系统设置 -> 应用 -> ThBox -> 通知中重新开启。

### Q9: 系统备份或换机迁移后节点丢失？
- 1.6.0 起，系统备份和设备迁移不再包含节点数据库，以防节点密码随备份泄露。换机请使用应用内的“备份与恢复”导出配置。

## 4. 自定义规则与外部规则导入

### Q10: 支持哪些规则文件格式导入？
- 在“路由资产（Assets）”页面导入 `.db` 文件（如 `geoip.db`、`geosite.db`），可以替换内置的 GeoIP / GeoSite 数据库。分流规则中的 `geoip:xx`、`geosite:xx` 会使用它们。
- 导入页面接受 `.db`、`.srs` 和 `.json`，列表显示格式、保存路径及使用说明，自定义文件可删除并撤销。替换前检查文件非空、大小与格式；这一步失败时保留原文件。文件已替换但版本信息写入失败时，会明确提示导入成功及元信息错误。
- `.srs` 与 `.json` 导入后不会自动启用。请在自定义配置的 `route.rule_set` 中定义 `type: local`，将列表显示的绝对路径写入 `path`，再由 `route.rules` 引用对应 tag。Preview 与正式版目录不同，请复制当前应用显示的路径。

### Q11: 订阅更新提示节点仍被引用？
- 订阅中的节点被删除或变化后，应用会检查代理链、前置/落地代理和路由引用。无法安全匹配时保留原数据并拒绝更新；点击“查看相关项目”调整相关引用再重试。已有重名节点只有在内容唯一匹配时才自动更新，歧义会明确提示。仅名称变化且内容能唯一匹配时，保留节点 ID。

### Q12: 恢复备份提示需要同时恢复节点与规则？
- 节点 ID 只在原数据库内有意义。只恢复某一部分时，若无法证明规则仍指向同一节点，会拒绝恢复；若旧备份本身没有节点信息，请重新导出包含节点与规则的备份。本分支 v2 规则-only 备份带引用指纹，可在节点身份匹配时恢复；v1 完整备份仍可读取。仅恢复节点或仅恢复设置会清除当前选择，需要重新选取节点。失败提示会区分原数据保留和提交成功但重启失败。

### Q13: Hysteria v1 分享为什么变成 `sn://`？
- 使用 Base64 认证时，标准 v1 链接不能保留二进制认证类型。应用使用通用链接保留原始配置；接收端需要支持该格式。跨客户端迁移请使用接收端支持的完整配置导入，避免把 Base64 文本误当成字符串密码。

### Q14: 在线规则更新失败后是否需要删除旧文件？
- 不需要。下载、大小/格式校验或替换失败时，原文件与版本标记保留。若文件已经更新而版本标记写入失败，会单独提示，可修复存储问题后重试。

### Q15: 编辑保存提示配置在编辑期间已变化？
- 自动订阅更新、其他编辑或删除可能已改变当前记录。本次保存没有覆盖新配置。请重新打开节点核对，必要时复制尚未保存的输入后再编辑。旋转或重建页面不会重置这项检查。

### Q16: Preview 为什么因缺少签名配置构建失败？
- 云端预览要求固定的 `OLD_*` 签名配置，避免每次构建使用不同 debug 证书而无法覆盖安装。Preview 仍使用独立包名，可与正式版共存。本机 debug Preview 与云端 Preview 的证书可能不同，迁移前先导出备份。


### Q17: 导出备份时切换页面或旋转后，文件还能使用吗？
- 本分支先保存私有快照，再打开系统保存界面，页面重建后继续使用同一份快照。若系统清理了缓存或写入失败，会明确提示重新导出，不会把空内容当作成功备份。导出文件仍未加密，请妥善保存。

### Q18: sing-box 节点的“内嵌出站依赖”是什么？
- 导入线性 `detour` 链时，依赖与当前节点一起保存为独立副本。可在该节点设置中编辑依赖 JSON；修改另一个同名节点不会改变副本，订阅更新则会替换它。缺失目标、引用环、重名或策略组不能拆分时，请使用完整自定义配置，不要删掉 detour 后假定连接方式相同。

### Q19: 停止时提示流量无法保存，应该怎样处理？
- 失败期间后台保留待保存统计并阻止新的运行及恢复操作。处理存储问题后，再次执行维护操作会重试。不要立即强制结束后台进程，否则内存中的待保存统计仍可能丢失；核心清理本身持续失败时需先处理该错误。
