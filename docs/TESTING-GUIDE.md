## ⚙️ 配置方法

### 对照组配置（不启用优化）
```json
{
  "type": "naive",
  "tag": "proxy",
  "server": "your-server.com",
  "server_port": 443,
  "username": "your-username",
  "password": "your-password",
  "tls": {
    "enabled": true,
    "server_name": "your-server.com"
  }
}
```

### 实验组配置（启用优化）
```json
{
  "type": "naive",
  "tag": "proxy",
  "server": "your-server.com",
  "server_port": 443,
  "username": "your-username",
  "password": "your-password",
  "connection_warmup": true,  ← 关键：添加这一行
  "tls": {
    "enabled": true,
    "server_name": "your-server.com"
  }
}
```

## 🎯 核心测试：冷启动性能

这是最重要的测试！

### 测试步骤

**配置A（对照组 - connection_warmup: false）**：
1. 完全关闭应用并清除后台
2. 使用配置A（不含 connection_warmup）
3. 启动应用并连接 VPN
4. 等待"已连接"状态
5. **立即**打开浏览器访问 https://x.com
6. 用秒表记录从点击到页面首屏显示的时间
7. 重复测试3次，取平均值

**配置B（实验组 - connection_warmup: true）**：
1. 完全关闭应用并清除后台
2. 使用配置B（包含 connection_warmup: true）
3. 启动应用并连接 VPN
4. 等待"已连接"状态
5. **立即**打开浏览器访问 https://x.com
6. 用秒表记录从点击到页面首屏显示的时间
7. 重复测试3次，取平均值

## 🔍 日志验证

### 查看预热日志

启用 connection_warmup 后，在应用日志中应该看到：

```
INFO  NaiveProxy started, version: xxx
DEBUG warming up connection to proxy server...
INFO  connection warmup completed successfully
```

### 查看日志方法
1. 打开应用
2. 设置 -> 日志级别 -> Debug
3. 连接 VPN
4. 查看日志输出

如果看到 "connection warmup completed successfully"，说明预热成功！

## 📊 快速对比测试

如果时间有限，可以这样快速测试：

1. **配置A**：关闭应用 -> 启动 -> 连接VPN -> 访问x.com（计时）
2. **配置B**：关闭应用 -> 启动 -> 连接VPN -> 访问x.com（计时）
3. **对比**：配置B应该明显更快（目标：快50%以上）

## ✅ 成功标准

优化被认为成功的条件：
- ✅ 配置B首次加载时间比配置A减少 **50%以上**
- ✅ 日志中有 "connection warmup completed successfully"
- ✅ 无明显的稳定性问题或崩溃
- ✅ 主观体验明显改善

## 🐛 如果遇到问题

### 预热失败
**现象**：日志显示 "connection warmup failed"
**影响**：不影响正常使用，只是首次请求仍会有延迟
**操作**：记录并反馈，但可以继续测试

### 性能无改善
**可能原因**：
1. 网络环境限制
2. 服务器响应慢
3. 其他瓶颈

**操作**：记录详细情况并反馈

### 应用崩溃
**操作**：
1. 立即记录崩溃日志
2. 在 PR 中反馈
3. 暂停测试
